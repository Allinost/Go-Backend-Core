# PostgreSQL 迁移（V3）

V3 的 Schema 只由本目录迁移管理，**生产禁用 AutoMigrate**。

## 连接约定

```env
APP_DATABASE_POSTGRES_MAIN_SEARCH_PATH=gobackendcore,public
```

- 表创建在 `gobackendcore` schema，`public` 仅兜底。
- 应用账号需要数据库 `CREATE` 权限；migrate 模块启动时会自动执行：
  `CREATE SCHEMA IF NOT EXISTS gobackendcore AUTHORIZATION CURRENT_USER`。
- 不需要授予应用账号 `public` schema 的建表权限。

## 文件

| 版本 | 文件 | 内容 |
|---|---|---|
| 001 | `001_init.sql` | `_migrations` |
| 002 | `002_system_config.sql` | 配置中心：`system_config` / `system_config_history` |
| 003 | `003_v3_ops.sql` | 主机台账、L1/L2 维护状态 |
| 004 | `004_v3_baseline.sql` | V3 基座/公共/PM 核心表 |
| 005 | `005_v3_pm_full.sql` | 里程碑/任务/依赖/风险/发布/基线/迭代等 |
| 006 | `006_v3_updated_at.sql` | 全表 `updated_at` 触发器（数据库时间兜底） |

## 执行

```http
GET  /api/v1/migrate/schema/migrations
POST /api/v1/migrate/schema/migrate
```

- 启动后 migrate 模块优先使用 PostgreSQL；MySQL 仅作 V2 兼容兜底。
- 迁移器会自动创建 `_migrations`，按版本顺序执行未应用文件。
- 每个文件可重复执行（`IF NOT EXISTS`）；失败修复后重新调用即可。

## 规则

- 已发布文件不可修改；变更必须新增 `006_*.sql`。
- 不使用 MySQL 专有语法：`AUTO_INCREMENT`、`ENGINE`、`TINYINT(1)`、`DATETIME`。
- 主键用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 时间用 `TIMESTAMPTZ`，JSON 用 `JSONB`，布尔用 `BOOLEAN`，金额用 `NUMERIC`。
- 软删除表使用部分索引：`WHERE deleted = false`。
- 迁移文件注释和字符串内不要出现英文分号，迁移器按分号拆分语句。
- 破坏性变更必须先备份，并在变更说明中写回滚步骤。
