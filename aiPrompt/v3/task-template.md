# 任务契约模板（V3）

> 复制到任务/PR 描述，填完再开始实现。

```markdown
# 任务契约：V3-Px-yy 标题

## 1. 目标
- ...

## 2. 非目标
- ...

## 3. 必读上下文
- docs/plans/V3-postgres-refactor-2026-11-18.md §__
- docs/projects/go-backend-core/v3/SOP.md §__
- aiPrompt/v3/context.md
- aiPrompt/v3/pg-rules.md
- 相关代码/迁移/模块文档：__

## 4. 验收标准
- [ ] 可执行测试/命令：__
- [ ] 接口断言/响应：__
- [ ] 迁移/回滚：__
- [ ] 文档/数据字典：__

## 5. 约束
- PG-only，`$n`，无 MySQL 方言
- 生产 `auto_migrate=false`
- 保持 `/api/v1`
- V3.0 不改业务模块；V2 冻结
- 公网相关：1Panel 托管 443→新机器 80；管理接口白名单；限流/审计
- 仅修改以下文件/目录：__

## 6. 交付物
- [ ] 代码
- [ ] 单元测试
- [ ] PG 集成测试（如涉及仓库）
- [ ] 迁移/数据字典（如涉及表）
- [ ] 文档/Swagger（如涉及 API）
- [ ] 任务日志/工时

## 7. 风险与回滚
- 风险：__
- 回滚：__

## 8. 验证记录（实现后填）
- 命令/结果：__
- 评审：__
- 未解决项：__
```

## 使用要求

1. 任务契约先于代码；高风险任务（Schema/迁移/认证/部署）需人工确认。
2. 实现过程中若发现契约不完整，先更新契约再继续。
3. 完成后把验证记录写回 developmentManager 任务日志。
