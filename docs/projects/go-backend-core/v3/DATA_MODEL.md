# Go-Backend-Core V3 数据模型

## 1. 约定

- 数据库：PostgreSQL 18
- schema：默认 `gobackendcore`，`search_path=gobackendcore,public`
- 主键：`BIGINT GENERATED BY DEFAULT AS IDENTITY`
- 时间：`TIMESTAMPTZ`，默认 `now()`
- 布尔：`BOOLEAN`
- JSON：`JSONB`
- 金额/工时：`NUMERIC`
- 软删除：`deleted BOOLEAN` + `deleted_at`，查询默认 `deleted=false`
- `updated_at` 由 `006_v3_updated_at.sql` 触发器统一刷新
- 表/字段注释见 `007_v3_table_comments.sql`

## 2. 迁移文件

| 版本 | 内容 |

## 3. 表分组

### 3.1 认证与权限

| 表 | 用途 |
|---|---|
| `users` | 用户账号 |
| `roles` | 角色 |

| `role_permissions` | 角色-权限 |

关系：

```
users 1─n user_roles n─1 roles
```

### 3.9 项目管理：风险 / 发布 / 基线

| 表 | 用途 |
|---|---|
| `zzz_development_manager_risk` | 风险 |
| `zzz_development_manager_release` | 发布记录 |
| `zzz_development_manager_baseline` | 计划基线快照 |

- 风险：概率 × 影响 → 等级，状态 `open/mitigating/closed/accepted`
- 发布：类型 `major/minor/patch/hotfix`，状态 `planned/deploying/deployed/rolled_back`
- 基线：保存里程碑/任务计划快照，用于范围/进度对比

## 4. 状态与枚举

| 领域 | 值 |
|---|---|
| 任务 | `todo/doing/blocked/review/done/cancelled` |
| 里程碑/迭代 | `planned/active/done/closed` |
| 风险 | `open/mitigating/closed/accepted` |
| 发布 | `planned/deploying/deployed/rolled_back` |
| 需求 | 按需求模块定义的状态机 |
| 主机 | `online/offline/error/unknown` |
| 维护 | `shutdown/migrate_return/migrate_no_return` |

## 5. 索引策略

- 项目/任务/风险/发布按 `project_id + status` 建部分索引
- 任务按 `milestone_id/iteration_id/requirement_id/parent_id/owner` 建索引
- 依赖按 `task_id/depends_on_task_id` 建索引
- 日志按 `task_id/created_at` 建索引
- 软删除表使用 `WHERE deleted=false` 部分索引
- 唯一约束同样排除软删除行

## 6. 数据迁移注意事项

- 只允许 V3.0 基座/公共/PM 表进入 allowlist
- V2 表名映射示例：`role_models→roles`、`tasks→scheduler_tasks`、`task_logs→scheduler_task_logs`
- 导入时处理 identity 序列重置
- FK 失败行自动重试；孤儿 `user_roles` 跳过
- 正式切换前必须跑 `rehearsal`
