# V3 AI 试点复盘

## 1. 试点范围

本轮用 V3 SOP 完成了多个真实任务：

- PG-only 基座与迁移
- 认证/RBAC/API Key/登录锁定
- 配置中心
- PM 核心与高级能力
- 主机台账 / SSH / 维护模式
- 对象存储故障降级 Redis 暂存
- 前端 V3 页面：任务/看板/风险/发布/迭代/基线/配置中心/系统状态

## 2. 有效做法

1. 先读 SOP + 台账，确认边界和验收。
2. 每轮只做一个可验证的纵向切片。
3. 后端先确保 `go build` / `go vet`，再补测试。
4. 前端每个页面完成后跑 `typecheck` + `build`。
5. 数据库变更必须走 migrations，不在应用里 AutoMigrate。
6. 运维能力默认降级，不阻塞主流程（RustFS/Redis 是典型例子）。
7. 台账随开发同步更新，避免 README 与 DB 状态漂移。

## 3. 发现的问题

- 测试二进制被本机 Application Control 策略拦截，Go 测试无法稳定执行；已用 `build`/`vet`/Node+pg 事务验证补位。
- 早期台账状态与实际完成度不一致，已从 README 重新同步并清理测试任务。
- 全量 SQL `?`→`$n` codemod 风险高，保留 `dbutil.Rebind` 运行期转换更稳。
- 部署/反代/恢复演练依赖真实环境，代码侧只能准备脚本与 Runbook。

## 4. 结论

V3.0 代码侧已基本收口，剩余项集中在真实环境部署、恢复演练和上线观察。AI 试点流程可继续用于 V3.1 业务模块迁移。
