# Go-Backend-Core V3 架构说明

## 1. 目标与边界

V3.0 是 PG-only 的新机器基座，目标是把 V2 的 MySQL 业务模块从运行时剥离，先交付：

- 认证 / RBAC / API Key
- 配置中心
- 项目管理（PM）
- 主机台账 / SSH 状态
- L1/L2 维护模式
- 文件存储与 Redis 暂存降级
- 数据迁移、备份、UAT 与部署文档

V2 业务模块（goodser / shopchecker / login3rd / ia）默认不注册，MySQL 默认不连接。需要兼容旧数据时通过 `cmd/v3migrate` 离线导入。

## 2. 部署拓扑

```
                 ┌────────────────────┐
                 │  公网/Nginx/1Panel  │
                 └─────────┬──────────┘
                           │ /api
                 ┌─────────▼──────────┐
                 │  Go-Backend-Core   │
                 │   :29090 / :29092  │
                 └───┬───────┬────────┘
                     │       │
        ┌────────────▼─┐   ┌─▼────────────┐
        │ PostgreSQL   │   │ Redis        │
        │ L1 / L2      │   │ 登录锁定/暂存 │
        └──────────────┘   └──────────────┘
                     │
              ┌──────▼───────┐
              │ RustFS/MinIO │
              │ 图片/文件     │
              └──────────────┘
```

- L1：V3 主入口、PG、Redis、运维入口
- L2：备份/迁移目标，使用 `APP_PROFILE=backup`
- ACloud：RustFS、外部工具，固定地址，不随 L1/L2 切换
- 前端 Go-Frontend-Core 通过 `/api/v1` 访问

## 3. 代码分层

```
cmd/                    启动与运维命令
internal/
  modules/              业务模块（auth/settings/ops/migrate/webhook/...）
  services/             可复用服务（storage/fileref/configcenter/migrate/...）
  database/             PG/Redis/S3 连接与健康检查
  middleware/           认证、RBAC、日志、恢复
  pkg/                  logger/errors/response/dbutil
migrations/postgres/    PG schema 迁移
zzz/developmentManager/ PM 模块（V3 核心业务）
zzz/...                 V2 legacy 模块（默认不加载）
```

模块统一实现：

```go
Name() string
Init(*config.Config) error
Close() error
RegisterRoutes(*gin.RouterGroup)
```

启动时按注册顺序初始化；`legacy_modules_enabled=false` 时不注册 V2 模块。

## 4. 数据存储

### PostgreSQL

- 唯一 V3 主库
- schema 由 `migrations/postgres` 管理，应用不 AutoMigrate
- 连接池、search_path、时区、fallback 由 `database.postgres.main` 配置
- 身份列使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- JSON 使用 `JSONB`，时间使用 `TIMESTAMPTZ`

### Redis

- 登录失败锁定（多实例共享，失败回退内存）
- 集成幂等缓存
- Webhook 限流/去重
- 对象存储故障时的文件暂存区 `v3:storage:stage`

### 对象存储

- RustFS 优先，MinIO 兜底
- 仅文件/图片能力，不阻塞后端启动
- `FallbackStore` 链路：S3 → Redis → 文件接口报错
- 后台每 30s 尝试把 Redis 暂存提交回 S3

## 5. 认证与权限

- JWT access/refresh
- RBAC：`roles` / `permissions` / `role_permissions` / `user_roles`
- API Key：只存哈希，支持 scopes、过期、撤销
- 登录失败锁定：`auth.login_max_failures` / `auth.login_lock_minutes`
- 自助注册默认关闭：`auth.allow_registration=false`
- 管理入口：`cmd/v3admin` 创建管理员

## 6. 配置中心

- 启动基线：env / config.yaml
- 运行时优先级：DB > 基线 > 默认值
- Schema 驱动，支持 string/int/bool/duration/json/secret
- 敏感项 AES-GCM 加密落库，接口只回掩码
- 变更：校验 → 持久化 → 应用 → 审计
- 支持热更新的项由模块注册 `Reloadable`
- 管理 API：`/api/v1/settings/config/*`

## 7. 项目管理（PM）

- 项目 / 里程碑 / 迭代 / 任务 / 依赖 / 日志
- 风险 / 发布 / 基线 / 评论 / 检查项 / 标签 / 任务资产
- 看板、路线图、周报、仪表盘、甘特、风险矩阵、发布日历
- 任务状态：`todo → doing → review → done`，支持 `blocked`
- 基线保存计划快照，发布记录包含变更摘要与回滚方案

## 8. 运维与维护

- 主机台账 `zzz_ops_host`：凭据 AES-GCM 加密，接口只回提示
- SSH 状态采集只执行固定白名单命令
- known_hosts 校验默认关闭，可配置开启
- L1/L2 维护模式：`shutdown` / `migrate_return` / `migrate_no_return`
- 维护状态、同步确认、反向同步确认、操作人、审计
- 系统状态页展示依赖健康、模块列表、存储降级与暂存积压

## 9. 迁移与备份

- `cmd/v3migrate`：plan/dump/load/verify/rehearsal/report
- allowlist 只允许 V3.0 基座/公共/PM 表
- `rehearsal` 在临时 schema 完整演练后删除
- `scripts/pg-backup.sh` / `pg-restore.sh`：自定义格式、校验和、保留策略
- `scripts/pg-restore.sh` 必须显式 `CONFIRM_RESTORE=YES`

## 10. 扩展约定

- 新模块放 `internal/modules/<name>`，实现模块接口
- 新表必须写 `migrations/postgres/NNN_*.sql`，不得依赖 AutoMigrate
- SQL 使用 PG 方言；需要兼容时使用 `dbutil.Rebind`
- 配置项通过 configcenter 注册 Spec，不把业务密钥写进 env
- 文件上传统一走 `storage.Storage`，不要直接依赖 minio client
