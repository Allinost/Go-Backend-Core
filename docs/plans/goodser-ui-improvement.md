# Goodser Web / 小程序 UI 现状分析与开发目标

> 审计范围：`Go-Frontend-Core` 的 Goodser、集成管理页面；`Goodser` 小程序 25 个页面
> 目标：在不改变现有后端契约的前提下，把 UI 从「功能可用」推进到「高频任务顺手、状态一致、可维护」

## 1. 结论

业务功能覆盖已经比较完整：库存、入库、出库、预留、组合包、捆、退货、统计、集成管理都已可用。当前主要问题不是缺功能，而是 **信息架构、页面组织、状态反馈和跨端一致性**：

1. **入口埋得太深**：小程序的退货、统计、组合包、系列视图全部藏在「设置」里。
2. **页面过度集中**：Web Goodser 单文件 4151 行、8 个 Tab、18 个弹窗，维护和响应式都吃力。
3. **缺少一等公民入口**：Web 没有独立的「退货单」Tab，只能从出库单详情进入。
4. **状态体系不完整**：加载多为文字提示，空态/错误/重试不统一，部分页面静默失败。
5. **组件和视觉未收敛**：小程序仅 4 个共享组件，样式里按行统计有 666 处硬编码颜色。
6. **移动端效率不足**：退货列表无搜索/分页，统计 30 根趋势柱在手机上过密。

## 2. 现状量化

| 指标 | 现状 | 说明 |
|---|---|---|
| Web Goodser 单页 | 4151 行 | 8 个 Tab + 18 个 `NkDialog` 全在一个文件 |
| Web Goodser 响应式 | 1 个 `@media` | 仅统计面板做了 720px 折行 |
| Web 集成管理 | 490 行 | 无断点，固定 1100px 宽度 |
| 小程序页面数 | 25 个 | 底部 Tab 仅 4 个 |
| 小程序共享组件 | 4 个 | `empty-state`、`order-card`、`product-card`、`search-bar` |
| 小程序硬编码颜色 | 666 处（按行） | 无 CSS 变量/设计 token |
| 小程序内联样式 | 24 处 | 动态样式与静态样式混用 |
| 小程序最大页面 | `settings/index.js` 542 行 | 配置、同步、业务入口混在一起 |
| 退货列表 | 无搜索、无分页 | 全量返回并在卡片内展开全部明细 |
| 统计趋势 | 默认 30 天 | 标签 18rpx，移动端可读性差 |

## 3. 问题清单

### P0：影响日常使用

#### 3.1 小程序导航层级过深

- 底部 Tab 只有「库存 / 出库 / 入库 / 设置」。
- 退货、统计、组合包与捆、系列视图都在「设置」页二级入口。
- 店主每天高频使用的退货与统计需要 3 次以上点击。
- 设置页同时承担账号、同步、缓存、状态码、标签、业务入口，职责混杂。

**影响**：功能被发现率低，新用户很难形成稳定操作路径。

#### 3.2 Web 信息架构按“功能堆叠”而非“任务”组织

- 商品、系列、组合包、捆、统计、出库、入库、目录共 8 个平级 Tab。
- 商品主数据、营销配置、数据统计、日常操作混在同一层。
- 退货没有独立入口，只能先找到出库单再进入详情。
- Tab 内再套大量弹窗，深层任务容易迷失。

**影响**：页面认知负荷高，退货与异常处理路径不直观。

#### 3.3 页面状态不完整

- 多数列表只有 `loading` 文案或 `NkLoading`，没有骨架屏。
- 空态、错误态、无权限态、重试动作不统一。
- 多个页面存在空 `catch` 或静默降级，用户不知道数据没加载成功。
- 删除/确认退货等操作确认文案不一致，没有撤销或结果回执。

#### 3.4 退货链路缺少集中管理

- Web 只能在出库单详情里查看/创建退货。
- 小程序退货列表没有搜索、状态分组之外的筛选、分页或按单号定位。
- 退货卡片默认展开全部商品行，长列表信息密度过高。
- 退货与出库单之间缺少清晰的关联跳转和状态时间线。

### P1：影响效率与一致性

#### 3.5 组件复用不足

- Web Goodser 的 Tab 内容、筛选栏、表单、详情弹窗都集中在一个文件。
- 小程序状态标签、数量步进器、统计卡、退货行、空态文案多处重复。
- 两端对“待确认 / 已确认 / 已取消 / 部分退货 / 已退货”的颜色和文案没有统一来源。
- 相同业务对象在 Web 与小程序使用不同的卡片结构和字段顺序。

#### 3.6 视觉规范未 token 化

- 小程序没有颜色、间距、圆角、字号变量，666 处颜色直接写死。
- 同一个蓝色/红色/灰色在不同页面存在细微差异。
- 次要文字大量使用 22–24rpx，低对比度场景可读性不足。
- 按钮高度、卡片圆角、分割线样式不统一。

#### 3.7 移动端可用性

- 统计页 30 根趋势柱 + 18rpx 标签，手机上难以点选和阅读。
- 部分固定底栏未处理 `safe-area-inset-bottom`（如出库单详情）。
- 退货、统计、营销页缺少下拉刷新以外的快捷刷新/筛选。
- 长表单（组合包、捆、商品编辑）没有步骤导航或吸底保存。

#### 3.8 桌面端响应式

- Goodser 只有统计面板一个断点，其他表格/卡片/弹窗在窄屏下会拥挤。
- 集成管理页无断点，固定 1100px 最大宽度。
- 弹窗宽度 400–520px，移动浏览器/平板下可用性差。
- 商品网格、订单卡片、筛选栏缺少小屏折叠策略。

#### 3.9 操作效率

- Web 商品列表没有批量操作（批量改状态、批量删除、批量导出）。
- Web 统计只有 7/30/90/365 天预设，没有自定义区间和导出。
- 退货列表没有按单号/商品/原因搜索。
- 组合包/捆编辑表单较长，缺少分组标题、校验摘要和保存前预览。

### P2：体验 polish

- 图标按钮缺少文字标签或 `aria-label`。
- Web 键盘焦点样式、禁用原因提示不完整。
- 图片加载失败没有统一占位。
- 空态插画/文案风格不统一。
- 列表切换时缺少过渡，容易产生“闪一下”的感觉。
- 统计与集成页缺少“最近更新时间”与手动刷新反馈。

## 4. 开发目标

### 4.1 总目标

让店主在 **3 次点击内完成高频任务**，让每个页面具备 **加载 / 空 / 错误 / 成功四态**，让同一业务对象在 Web 与小程序保持 **一致的名称、颜色和操作顺序**。

### 4.2 可验收目标

| 维度 | 目标 |
|---|---|
| 信息架构 | 小程序底部 Tab 覆盖库存、出库、退货、统计、我的；业务入口移出设置 |
| Web 结构 | Goodser `index.vue` 降到 800 行以内，按 Tab 拆分子组件；新增独立「退货」Tab |
| 组件复用 | 小程序共享组件 ≥ 12 个；Web 抽出状态标签、空态、错误态、统计卡、确认弹窗 |
| 状态覆盖 | 100% 列表页具备加载骨架、空态、错误重试；100% 表单具备字段级校验 |
| 防误操作 | 所有删除/取消/确认退货有二次确认；关键操作显示成功/失败结果 |
| 效率 | 出库、退货、统计、组合包下单均 ≤ 3 次点击；退货支持搜索/筛选 |
| 移动端 | 点击热区 ≥ 88rpx；正文 ≥ 26rpx；320px 宽度无横向滚动；趋势图可点选 |
| 视觉规范 | 颜色/间距/字号/圆角 token 覆盖率 ≥ 90%；禁止新增硬编码颜色 |
| 质量 | 核心 6 条流程自动化冒烟通过；无 console error；UI Checklist 全绿 |

## 5. 分阶段计划

### Phase UI-1：基础与导航（2–3 天）

- 小程序底部 Tab 调整为「库存 / 出库 / 退货 / 统计 / 我的」。
- 设置页只保留连接、同步、缓存、字典/状态码/标签等配置项。
- Web Goodser 新增「退货」Tab，支持列表、筛选、确认/取消。
- 建立小程序 `app.wxss` 设计 token：颜色、字号、间距、圆角、阴影。
- 抽出基础组件：`status-tag`、`empty-state`、`error-state`、`skeleton`、`quantity-stepper`、`confirm-dialog`。

**验收**：高频入口 ≤ 1 次点击进入列表；设置页不再承载业务入口；新增颜色 0 处硬编码。

### Phase UI-2：高频流程（3–5 天）

- 小程序退货列表：搜索、状态筛选、分页/加载更多、卡片折叠明细。
- 小程序统计：趋势柱可点选、显示当日明细、默认 7 天、支持快捷区间。
- 小程序出库创建：步骤化（选商品 → 确认数量/组合 → 提交），吸底操作栏。
- Web 商品列表：批量选择、批量状态/删除、导出。
- Web 退货与出库详情：状态时间线、关联单据跳转、退货明细折叠。
- Web 统计：自定义区间、导出 CSV、空数据引导。

**验收**：核心流程不出现“找不到入口/不知道下一步”；列表 100 条数据下可正常操作。

### Phase UI-3：一致性与响应式（2–3 天）

- Web Goodser 按 Tab 拆分为独立组件，`index.vue` < 800 行。
- 统一状态标签、卡片、按钮、表单间距、空态文案。
- Web 增加 1024/768/480 断点；弹窗在窄屏改为全宽/底部抽屉。
- 小程序补齐 safe-area、图片占位、加载骨架、错误重试。
- 集成管理页补齐连接器测试结果、事件筛选与空态。

**验收**：320px–1440px 无横向滚动；同一状态在两端颜色/文案一致。

### Phase UI-4：QA 与度量（1–2 天）

- 建立 UI Checklist（状态、交互、文案、响应式、可访问性）。
- 小程序 automator 冒烟：库存、出库、退货、统计、组合包/捆下单。
- Web 关键页面截图基线（商品、退货、统计、集成）。
- 收集点击路径与失败率，形成下一轮优化清单。

## 6. 优先级建议

| 优先级 | 事项 | 价值 | 成本 |
|---|---|---|---|
| P0 | 小程序 Tab 重构 + 设置页瘦身 | 高 | 中 |
| P0 | Web 退货 Tab + 集中退货列表 | 高 | 中 |
| P0 | 四态组件与错误重试 | 高 | 低 |
| P1 | Web Goodser 拆分组件 | 中高 | 中 |
| P1 | 退货搜索/筛选/分页 | 高 | 低 |
| P1 | 小程序 token 化 + 共享组件 | 中高 | 中 |
| P1 | 响应式与窄屏弹窗 | 中 | 中 |
| P2 | 批量操作、导出、自定义统计区间 | 中 | 中 |
| P2 | 可访问性与微交互 | 低中 | 低 |

## 7. 约束与非目标

- 不改变现有后端接口与业务状态机，UI 改造只做展示与交互层。
- 不做一次性大重写，按 Tab/页面逐步拆分，保证每步可回滚。
- 不引入新的 UI 框架，继续使用 NKUI 与小程序原生组件。
- 不为了视觉效果牺牲库存、退货等关键数据的可读性。
- 所有改动继续遵循 V2 SOP：测试、文档、`sop-check` 同步。

## 8. 建议的第一个 Sprint

1. 小程序底部 Tab 调整为 5 个，设置页移除业务入口。
2. Web 新增「退货」Tab，复用现有退货接口。
3. 建立小程序 token 与 6 个基础组件。
4. 退货列表增加搜索、状态筛选、加载更多。
5. 补 UI Checklist 与 5 条 automator 冒烟脚本。
